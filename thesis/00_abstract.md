# Abstract

Freelancers with irregular income need to know when a transaction, an expense or a payment received, is unusual and why. This thesis asks whether a deep-learning detector is needed for that, and builds a pipeline that flags unusual amounts, explains each flag in plain language, and produces an educational tax set-aside note. I evaluate it on three datasets: a public, synthetic-looking personal-finance dataset (BudgetWise: 15,900 rows, 150 users, rupees), real anonymized bank data (Berka: 1.06 million transactions, 4,500 accounts), and a simulation I built with habits and labeled anomalies. Auditing the first dataset showed that the original loader silently discarded 69% of the rows, that windows mixed income with expenses and contained almost no income, and that the class-project evaluation, which injected values outside the range any real input can take, did not measure realistic detection; re-evaluated by changing one raw amount, the original detector was at chance. Scaling each amount relative to the user's typical amount made an LSTM autoencoder useful, but not better than simple rules. On BudgetWise it flagged 41.0 ± 3.7% of tenfold spikes at a 5% false-positive rate while a one-line rule reached 73.6 ± 4.1% when told the direction; on real bank expenses a rule using variability-aware scaling (each amount judged against how much that history normally varies) caught 43 ± 1% of 50% changes against 14 ± 6% for the best autoencoder, a rule using log-ratio scaling caught 5% to 7%, and the variability-aware scaling was the largest effect found; in the simulation a one-line rule was best or tied at every habit level, and no detector found anomalies that break a pattern without being large (seasonal and duplicate). For explanations, a deterministic fact layer, a small local language model, and an automatic grounding check with a template fallback produced text that was fully correct for 95% of 20 sampled flags in the final round, against 100% for a template, which is statistically indistinguishable. The contributions are a data and evaluation audit, evidence that input scaling matters more than the model for amount-based detection, and a verification-first explanation design, with the negative result that the deep model was not needed.
